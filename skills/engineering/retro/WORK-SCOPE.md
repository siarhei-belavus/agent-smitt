# Work scope discovery

## Establish membership

Start from the user's selected chat, set of chats, Review Proposals, or delivery. Record the intended boundary. A selected specification delivery includes its member tickets; a selected ticket does not include its siblings merely because they share a coordinator.

Follow coordinator checkpoints, ticket relationships, execution references, and recorded delegation to implementation, validation, review, correction, and recovery sessions. Include subagent histories, delegated chats, archived attempts, and superseded attempts when their recorded relationships put them in scope. Read through the host's available session tools, local logs, and configured project records, following pagination.

Use parent records to locate the selected work without expanding into unrelated work. A mention or a shared project name alone does not establish membership. Record the relationship that brought each source into scope. Report unresolved references, inaccessible subagent histories, and evidence lost during cleanup. Ask for a missing reference only when the intended work cannot be identified; continue independently accessible work.

## Build the source index

Keep one entry per history or review source with its stable reference, membership reason, project, delivery or ticket when known, parent or delegation reference, available date bounds, archive state, and read coverage. Deduplicate histories reachable through several paths.

Creation and last-update times help locate histories; they do not establish which instructions governed a particular action. Readers recover relevant event times and effective versions from the source segments.

Before full-history reads, give evidence workers bounded source assignments and both branches' questions. A reader that discovers another related source reports its reference and membership evidence to the coordinator. The coordinator updates the index and assigns it, avoiding duplicate collection.

## Define independent incidents

Work membership and incident identity are separate. Several chats can describe one failure or attempt. A common coordinator can also contain distinct pieces of work. Group by the underlying issue, delivery, attempted remedy, and causal event rather than counting chat titles or workers.

Recovery, retries, implementation, and review of the same incident provide more evidence about that incident, not independent support for its remedy. When independence is uncertain, disclose the relationship and avoid treating the cases as independent samples.

For work still in progress, include only events before the recorded cutoff. Keep later outcomes unknown.

Done when every discovered source has a membership decision and collection status, and each comparison has an incident identity or an explicit uncertainty.
