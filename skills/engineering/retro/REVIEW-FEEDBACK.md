# Review feedback

Read [provider concepts](references/bundled/federated-workflow/PROVIDER-CONCEPTS.md) for Review Proposal, Review Feedback, and Code Host terminology.

## Collect the user's comments

Identify Review Proposals from explicit user references and links in the selected sessions, delivery checkpoints, and tickets. Include relevant open, merged, and closed proposals and previous attempts. Use the repository's Code Host binding and available read tools. Keep collection read-only.

Establish the user's provider identity from explicit context or verified account mappings. A tool's authenticated account alone does not establish who the user is. If attribution is ambiguous, ask which account or accounts are theirs while collecting accessible context, and report the uncertainty.

Read general comments, review summaries, and inline discussions through every available page. Include resolved and closed discussions and comments on outdated diffs. Retain the user's remarks and the surrounding replies needed to interpret them. Record proposal and comment links or stable identifiers, authorship, timestamps, and referenced revisions. Report inaccessible proposals, missing discussion types, truncated history, or unavailable comment versions as coverage gaps.

Done when every discovered Review Proposal has an accounted-for collection result and the user's comments are attributable or explicitly uncertain.

## Recover the correction and outcome

For each relevant remark, inspect its original code or diff context and referenced revision. Follow the discussion and subsequent changes up to the retrospective's observation cutoff to determine what was requested and what happened. A resolved discussion alone does not prove an implementation or withdrawal of the user's request. Preserve the reviewed source revision separately from later changes and merge results, and report missing revision evidence.

Carry the remark, surrounding evidence, and observed outcome into the main skill's correction analysis. Distinguish the user's own statements from replies and automated feedback. Connect a remark and its retelling in chat to one incident. Use the original comment reference when proposing a documentation, standards, tooling, or check change.

Done when each candidate lesson has its source remark and observed outcome or an explicit evidence gap.
