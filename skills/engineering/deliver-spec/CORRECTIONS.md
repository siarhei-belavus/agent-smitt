# Specification corrections

Use this branch for in-scope combined-result failures or actionable final-review feedback. Resume the same Specification through [recovery](RECOVERY.md) first. Record the feedback's permanent references, affected requirements and repositories, accepted disposition, and remaining actions on the Specification. Closed delivery tickets remain historical results; an additional ticket is not required.

## Establish correction authority

Read complete actionable feedback through each proposal's Code Host binding, including resolved or superseded dispositions needed to interpret it. Feedback identifies requested changes; it does not override accepted requirements. Resolve ambiguous or conflicting intent with the human before affected implementation.

Bound writes to repositories authorized by the agreed tickets and the accepted specification outcome. A read-only reference is not writable. Additional writable repositories or changed requirements require explicit human approval and durable reconciliation on the Specification. After approval, update the recorded scope and authority, obtain fresh accepted Context Assembly where authority changed, and continue in this Specification without a mandatory ticket.

For an affected final proposal already merged, preserve its exact source and confirmed result. Explain and obtain agreement for a follow-up proposal in that repository before preparing its new source branch from the current appropriate target. Keep that branch, target, and proposal in the same specification record. Still-open affected proposals retain their existing source branches. Unaffected merged repositories remain read-only historical results and do not block corrections elsewhere.

**Complete when:** every actionable item has an in-scope assignment or an explicit unresolved human decision, and any follow-up proposal has agreement and recorded provenance.

## Implement and integrate

Use Standalone `implement`, not a ticketless `deliver-ticket`. Supply the unchanged accepted Specification Decision Context path, the invocation and accepted feedback authorizing writes, explicit Repository Scope entries, required outcomes, Repository References, verified writable worktrees and branches, exact Fixed Review Bases, applicable Settled Seams and test approaches, Validation Obligations, and repository validation commands. The Specification remains planning authority without gaining a Repository Scope of its own. Record the executable correction assignment in the specification checkpoint.

Normally assign one writer per affected repository to its suitable isolated specification worktree at the recorded branch and exact starting head. Reuse verified worktrees; preserve unknown work for reconciliation. Ensure previous ticket coordinators or correction workers cannot write the same state concurrently. Record launch intent and runtime references and recover uncertain starts through the same specification recovery rules.

When independent corrections in one repository justify parallel writers, give each an isolated temporary branch and worktree at a pinned base. Integrate their attributable results into the specification branch through one owner, preserving both intents. Resolve in-scope conflicts, or pause semantic conflicts for a human decision. Keep temporary resources until their results are accounted for; automatic specification cleanup remains outside this skill.

`implement` owns implementation validation and its standalone independent review. Verify its exact-head results and dispositions. Its correction diff review does not replace the final target-to-specification review. Return to step 4 of `deliver-spec` for affected whole-specification validation and independent review of the combined heads, then step 5 to publish those heads to the same open proposals or agreed follow-up proposals.

**Complete when:** every implemented feedback item has an attributable disposition, the integrated result has fresh applicable validation and independent review, and updated proposals and remaining human actions are recorded on the same Specification.
