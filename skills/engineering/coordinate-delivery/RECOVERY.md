# Recovery

Read [planning artifact contracts](references/bundled/federated-workflow/PLANNING-ARTIFACTS.md) and [lifecycle artifact contracts](references/bundled/federated-workflow/LIFECYCLE-ARTIFACTS.md) completely before classifying recovery.

The Resume Gate proves that exactly one durable source authorizes the next Execution Attempt and determines whether work continues under existing intent or follows a Resumption Plan.

Re-read the ticket, dependencies, routing, assignees, coordination notes, Review Proposals and feedback, Published Delivery Heads, and evidence bindings. Validate every lifecycle record against [the artifact invariants](references/bundled/federated-workflow/LIFECYCLE-ARTIFACTS.md#record-invariants). Durable provider state must suffice in a fresh context; live memory supplies no missing fact. Preserve local-only dirty work but exclude it from authority until a human establishes provenance.

Restore execution choices before applying invocation defaults or classifying a terminal handoff. Read the latest complete checkpoint's selected targets, immutable launch commits, current Fixed Review Bases, and merge permission. Omitted arguments retain those choices. Conflicting supplied arguments enter the human boundary without changing them; only explicit reconciliation through the existing Human Response and, when required, Resumption Plan can authorize a change. A legacy record without choices retains its historical configured target and disabled merge permission only when proposal targets and recorded provenance agree. Missing or contradictory historical target evidence requires reconciliation, not a guess from today's configuration.

A checkpoint with pending option resolution retains its supplied instructions. After its authority boundary is resolved through the Resume Gate, finish option resolution against the accepted ticket scope before preparation. Do not interpret pending choices as legacy defaults.

Reconcile every proposal's merge state against provider truth before retry or handoff. For a recorded merge operation, use only [outcome reconciliation](AUTOMATIC-MERGE.md#reconcile-the-outcome), retaining its operation reference. If the provider confirms a previously unrecorded merge, retain its exact source, target, result revision, and evidence and repair the missing record after the Resume Gate. An observed merge without recorded permission does not retroactively authorize automatic merge.

Treat an accessible Execution Worktree as reusable host state, not recovery authority. Verify its Repository Reference, selected target, intended delivery branch, launch commit, current Fixed Review Base, current head, and provenance from current context, Execution Checkpoint, handoff, completed Human Response, or Resumption Record. Preserve an identity mismatch or unknown dirty state and enter the [human-boundary branch](HUMAN-BOUNDARY.md). When the worktree is absent or unavailable, reconstruct it from its latest Published Delivery Head, provider-retained source revision for a merged proposal, or recorded target launch commit without treating the old local path as required state.

Classify a matching handoff before the Resume Gate. When its ticket, deterministic bundle key, execution choices, exact source heads, proposals, and evidence match current provider truth, the Delivery Bundle handoff is complete, and no unresolved lifecycle record remains, treat the delivery as terminal: report the existing handoff and return without a new request, claim, Resume Gate, or mutation. With automatic merge allowed, require every changed proposal's confirmed merge result. Compare historical source/result revisions, not the current target tip; unrelated later target advancement does not reopen a completed delivery. With merge disabled, an otherwise matching human handoff remains terminal after a human merges its proposals. When delivery results are complete but the handoff note or final effects are incomplete, continue through the Resume Gate and then read [handoff-only recovery](HANDOFF-ONLY.md). A contradictory handoff enters the [human-boundary branch](HUMAN-BOUNDARY.md).

Use exactly one Resume Gate source:

- an Execution Checkpoint plus completed Human Response;
- [actionable Review Feedback](REVIEW-FEEDBACK.md) after a completed review round; read that branch to qualify the source, then continue here;
- [runtime-proven termination](RUNTIME-TERMINATION.md) plus reconstructed Execution Checkpoint; read that branch to qualify the source, then continue here.

An unresolved escalation-bearing request takes precedence. Mixed sources, multiple active requests, incomplete chains, contradictory revisions, missing records, or unreconciled local-only work enter the [human-boundary branch](HUMAN-BOUNDARY.md).

The ticket must be open and explicitly returned to exactly `ready-for-agent`. Retain an activation-authority claim already acquired and verified for this Coordinator Activation; otherwise require the ticket to be unassigned, then acquire and verify the Workflow Identity claim. A foreign or interrupted claim qualifies only through [runtime termination](RUNTIME-TERMINATION.md). Select `continue` for Review Feedback or runtime termination. For a completed Human Response, select `continue` or `replan`; `replan` requires an execution-ready human-produced or explicitly delegated Resumption Plan.

## Evidence validity

Compare every recorded evidence dependency with current provider revisions. A changed delivery head invalidates its repository validation and Standards result, every cross-repository result it influences, and Bundle Spec. A changed influencing Validation Source commit invalidates only dependent cross-repository evidence and Bundle Spec.

A changed Fixed Review Base invalidates the affected Standards result and Bundle Spec; validation of a synchronized result also follows the changed-head rule. Target advancement alone is a merge-readiness change, not a new delivery head or proof of integration. Before an outstanding automatic merge, return to target synchronization and applicable evidence refresh. For a confirmed merge, preserve the historical source/result pair and its verified relationship to the evidence. A different commit ID from squash or rebase alone does not invalidate identical validated content; an unproven relationship enters the human boundary.

Preserve confirmed merged repositories during partial success. Merges across repositories are not atomic. Their immutable revisions remain available for read-only checks and reviews. Refresh evidence required by the rules below, but never dispatch implementation, republish, reset draft state, or retry merge for an already merged proposal. If completing the bundle now requires changing merged code, enter the human boundary for an explicit follow-up plan. Partial success grants neither rollback authority nor whole-bundle completion.

At the Resume Gate, apply the Authority input rule from [Validate the delivery contract](SKILL.md#2-validate-the-delivery-contract). Reuse the retained `Complete` Context Pack when its path remains available and readable in the live Coordinator context. A fresh agent context normally has no usable runtime-local path, so invoke Context Assembly once there and retain the new `Complete` path. A human response, Review Feedback, or return to the Resume Gate alone does not require reassembly.

When reassembly changes the Authority input, invalidate every prior Standards and Bundle Spec result that depended on the previous input and require fresh reviews. This conservative invalidation does not by itself invalidate repository validation or cross-repository evidence; preserve those when their complete delivery-head and Validation Source commit dependency sets remain unchanged. When the retained Authority input is reused, preserve reviews and evidence whose other dependencies remain unchanged. This paragraph is the sole owner of recovery evidence classification for Authority input reuse and reassembly.

## Resume execution

Publish and re-read the [Resumption Record](references/bundled/federated-workflow/LIFECYCLE-ARTIFACTS.md#resumption-record) before any new Execution Attempt or downstream mutation. Revalidate the complete delivery contract from the current accepted Context Pack and revalidate Repository Resolution, including instructions, bindings, canonical context, and ADRs, against repository truth. Do not repeat the pack's authority reads outside Context Assembly. When that authority remains valid, jump exactly to the record's next permissible step, which must name the earliest invalidated prerequisite; reuse already-complete preparation only after worktree identity and provenance validation, and reuse implementation, publication, and evidence whose prerequisites, influencing delivery heads, and Validation Source commits remain unchanged and which the conservative Authority input rule above did not invalidate.

**Complete when:** either the completed matching handoff is proven terminal, or exactly one source and allowed disposition are proven, the claim and launch heads match provider truth, one current Authority input has been reused or reassembled, its dependent review evidence is current, evidence is otherwise classified by influence, and the Resumption Record precedes the next attempt.
